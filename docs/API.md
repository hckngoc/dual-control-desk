# API contract

All protected routes require `Authorization: DPoP <access-token>` plus the `DPoP` header generated by Tide's SDK `secureFetch`. Do not manually add a stale Bearer header. The server's expected public origin is `APP_ORIGIN` (default `http://localhost:3000`); untrusted forwarded headers do not choose the signed target.

| Method | Route                                             | Role                      | Result                                                |
| ------ | ------------------------------------------------- | ------------------------- | ----------------------------------------------------- |
| GET    | `/api/health`                                     | Public                    | Service metadata; not a realm readiness certificate   |
| GET    | `/api/config`                                     | Public                    | Public adapter metadata                               |
| GET    | `/api/me`                                         | Authenticated             | Verified subject, display name, realm roles, expiry   |
| GET    | `/api/expenses`                                   | Any app role              | Visible requests, digest, nonsecret approval metadata |
| POST   | `/api/expenses`                                   | requester                 | Immutable request, 201                                |
| POST   | `/api/expenses/{id}/{digest}/finance-approver`    | finance-approver          | Record/renew signed approval                          |
| POST   | `/api/expenses/{id}/{digest}/compliance-approver` | compliance-approver       | Record/renew signed approval                          |
| POST   | `/api/expenses/{id}/{digest}/execute`             | payment-executor          | Independent mock rail result                          |
| GET    | `/api/audit`                                      | auditor/reviewer/executor | Latest 200 application events                         |

Create body:

```json
{
  "title": "Community clinic equipment",
  "payee": "Synthetic Medical Supplies",
  "account": "DEMO-ACCOUNT-001",
  "amount": 75000000,
  "evidence": "SYNTHETIC-INVOICE-2026-001"
}
```

Currency is fixed to VND. Amount is an integer from 10,000,000 to 100,000,000,000 VND. `requester`, `id` and `createdAt` are server-generated. No PATCH, role-grant or bulk approve endpoint exists. Approval/execute bodies are `{}`; operation identity is bound to the path.

Success example from rail:

```json
{ "receipt": "MOCK-<digest-prefix>", "realMoney": false }
```

The private mock rail exposes `GET /health` and `POST /payments` on port 4100. Payment input is `{expense, receipts:[{token,proof,lane}, ...]}`; do not publish real evidence or tokens. Missing or invalid signed evidence fails even if the caller edits the desk database. Repeated requests for the same ID and digest produce the same receipt without a second ledger insert, while proofs remain valid.

Errors: 400 invalid data; 401 invalid/missing authentication; 403 forbidden role/self-approval; 404 missing request; 409 digest/state/identity conflict; 412 independent payment verification failed; 413 oversized body; 500 unexpected app error (for example rail unavailable). There is no simulated success response when the rail is down.
